## 1. Где хранить манифесты мини-приложений (вместо LocalStorage)

Хранить критические данные (манифесты, права, пути к установленным файлам) в `LocalStorage` ненадежно:
- WebView на Android может сбрасывать `LocalStorage` при очистке кэша или сбое процесса.
- В `LocalStorage` нет транзакций, а размер ограничен (обычно 5–10 МБ).
- Кэш браузера стирается вместе с `LocalStorage` при переустановке или нехватке памяти.

### Перспективные варианты:
1. **IndexedDB (на уровне оболочки)**:
   - Оболочка держит базу `MappHubDB` с таблицами `apps` (манифесты, права, версия) и `storage` (ключ-значение для `storage.*`).
   - Мини-приложения не имеют прямого доступа к IndexedDB: все операции идут через RPC-мост (`storage.get`, `miniapp.install`), где оболочка валидирует права и подставляет `appId`.
2. **Нативная файловая система (через Capacitor Filesystem API)**:
   - Архивы мини-приложений распаковываются в защищенную песочницу устройства (`Filesystem.Directory.Data`).
   - `mappmanifest.json` каждого установленного приложения лежит на диске вместе с его HTML/JS файлами.
   - Оболочка читает манифесты с диска при старте. Это самый надежный подход, превращающий оболочку в полноценный мини-рантайм.

## 2. Предложение по полному набору API («на все случаи жизни»)

Чтобы экосистема мини-приложений была самодостаточной (в стиле Telegram Mini Apps и WeChat), предлагаю расширить набор модульных API-экшенов, разбив их по категориям. Каждый экшен реализован как отдельный файл `js/api/<category>/<action>.js` и защищен моделью разрешений (`docs/permissions.md`).

### Категория `device` (Устройство и окружение)
- `device.info` — платформа, экран, тема, язык (уже есть).
- `device.vibrate` — тактильная отдавля (вибрация по паттернам). Разрешение: `device.vibrate` (нативные функции).
- `device.clipboard` — чтение и запись в буфер обмена. Разрешение: `device.clipboard`.
- `device.network` — статус сети (online/offline, тип соединения).

### Категория `storage` (Изолированное хранилище)
- `storage.get`, `storage.set`, `storage.remove`, `storage.clear` — работа с ключами конкретного мини-приложения (уже частично есть, переносится на IndexedDB/файлы). Разрешение: не требуется (песочница).
- `storage.globalGet`, `storage.globalSet` — общие ключи, доступные только по явному разрешению межприложенческого обмена.

### Категория `ui` (Интерфейс и системные окна)
- `notifications.alert`, `notifications.confirm`, `notifications.prompt` — системные модальные окна оболочки (alert уже есть). Разрешение: не требуется.
- `ui.toast` — всплывающие легкие уведомления (тосты) внизу экрана. Разрешение: не требуется.
- `ui.openLink` — открыть внешнюю ссылку в системном браузере (не внутри iframe). Разрешение: `ui.externalUrl`.

### Категория `media` (Мультимедиа)
- `media.playSound` — воспроизведение звуковых эффектов из папки оболочки.
- `media.camera` — сделать фото или выбрать файл из галереи. Разрешение: `device.camera`.
- `media.share` — системное меню «Поделиться» (текст, ссылка, файл). Разрешение: не требует или требует в зависимости от данных.

### Категория `geo` (Геолокация)
- `geo.getCurrentPosition` — получить текущие координаты. Разрешение: `device.geolocation`.

### Категория `shell` (Управление оболочкой и навигация)
- `shell.navigate` — переход между мини-приложениями (нужна проверка прав на запуск чужих аппов).
- `shell.checkUpdate`, `shell.installUpdate` — обновление оболочки (уже есть частично).
- `shell.setTokens` — изменение дизайн-системы / CSS-токенов (уже есть).

### Категория `interapp` (Межприложенческий мост — для маркетплейса и связи игр)
- `interapp.listInstalled` — список установленных мини-приложений. Разрешение: `interapp.read`.
- `interapp.call` — вызов RPC-метода другого мини-приложения (с согласия пользователя). Разрешение: `interapp.call`.

## 3. Принятые решения (ноябрь 2026)

### Реестр установленных приложений
- Файл `apps.json` в каталоге данных оболочки. Одна запись на приложение: `appId`, `name`, `version`, `manifestUrl`, `permissions` (выданные), `requestedPermissions`, `installedAt`, `path`.
- Установка дописывает запись, удаление убирает её, обновление заменяет версию и манифест.
- Запись пишется атомарно: во временный файл, затем переименование. Так обрыв процесса не портит реестр.
- Версия `apps.json` хранится в нём же (`schemaVersion`) для будущих миграций.

### Устройство (`device`)
- `device.info` — оставить.
- `device.vibrate` — убрано из плана.
- `device.clipboard` — через HTML Clipboard API внутри iframe. Для записи нужен атрибут `allow="clipboard-write"`. Чтение требует разрешения `device.clipboard`.
- `device.network` — оставить по мере надобности.

### Хранилище (`storage`)
- Отдельного API-хранилища пока нет. Мини-приложения используют собственный `localStorage`.
- **Риск:** iframe с `sandbox="allow-same-origin"` работает с origin оболочки, поэтому `localStorage` у всех мини-приложений общий, и они могут прочитать ключи оболочки (`installed_app_*`, `mapp_shell_settings`). Это надо закрыть до релиза: убрать `allow-same-origin` либо вынести служебные данные оболочки из `localStorage`.

### UI
- `notifications.alert`, `notifications.confirm`, `notifications.prompt` — системные модальные окна оболочки.
- `ui.toast` — короткое уведомление внизу экрана без кнопок, не блокирует работу.
- `ui.openExternal` — открыть ссылку во внешнем приложении телефона (системный браузер Chrome или другой, выбранный по умолчанию). Реализуется через Capacitor Browser или Intent. Разрешение `ui.externalUrl`.

### Медиа и системные действия
- `media.camera` — фото или выбор файла из галереи. Разрешение `device.camera`.
- `media.share` — системное меню «Поделиться».
- `geo.getCurrentPosition` — разрешение `device.geolocation`.

### Оболочка и приложения (разделение)
- Оболочка: `shell.checkUpdate`, `shell.installUpdate`. Оболочка сама себя не заменяет, поэтому `installUpdate` открывает APK для системного установщика.
- Приложения: `apps.checkUpdate`, `apps.install`, `apps.uninstall`, `apps.list`. `apps.list` требует разрешение `apps.read`.
- `shell.navigate` переименовать в `apps.open`.
- `interapp.*` переименовать в `apps.*` (вызов методов другого приложения — `apps.call`, с согласия пользователя).

### Темы (`themes`)
- Наборы токенов хранятся в файле `themes.json` в каталоге данных.
- Встроенные темы «Светлая» и «Тёмная» зашиты в код, поэтому сброс всегда возможен, даже если файл потерян.
- Методы: `themes.list`, `themes.get`, `themes.setActive`, `themes.create`, `themes.update`, `themes.delete`, `themes.reset`.
- Встроенные темы нельзя удалить или переименовать. `themes.reset` возвращает их к заводским значениям.
- Мост при старте запрашивает активную тему и инъектирует токены как CSS-переменные `--app-*`. При изменении оболочка рассылает обновление всем открытым приложениям.
- Чтение токенов доступно без разрешения. Изменение через `themes.setActive` и `themes.update` требует разрешения `themes.write`, так как меняет вид всей оболочки.
