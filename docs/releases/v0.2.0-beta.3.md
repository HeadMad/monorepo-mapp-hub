## MappHub Shell v0.2.0-beta.3

### Added
- Bundled mini-apps (`launcher`, `sample-game`, `theme-editor`) are copied from APK assets into `noBackupFilesDir/miniapps/<appId>/<version>/` by the native layer (`MappSystem.installBundledMiniApp`) and registered in `system_registry`.
- The shell now opens mini-apps on `https://miniapp-<appId>.local/` instead of the shell origin. The bridge (`MappHostBridge`) accepts their `storage.*`, `theme.*` and `ui.getThemeTokens` calls.
- Theme editor is part of the bundled set.

### Changed
- Mini-apps load `MappHub.js` from `https://mapp.local/MappHub.js`.
- Changelog generator and release notes are in English.

### Fixed
- The runtime called `startMappHostBridge()` without importing it, which would throw on startup.
- The bridge no longer answers "Method not found" for methods it does not handle, so runtime API calls are not answered twice.

### Known limitations
- Not tested on a physical Android device. Native code was only parse-checked locally; the full compile runs in CI.
- Bundled mini-apps are re-copied from assets on every launch.
- Mini-app `archiveUrl` entries in `mappmanifest.json` still point to zip files that are not in the repository.
- Opening mini-apps directly from the repository (without the APK) no longer works for `MappHub.js`, which is now served by `mapp.local`.
