## MappHub Shell v0.2.0-beta.13

### Fixed
- `https://mapp.local/theme.css` no longer returns 404. `MappLocalAssetHandler` looked for a static `public/assets/theme.css`, and the fallback generator it was designed to run (`public/assets/<name>.js`) was never written, so every theme reload ended in `Not found`. The theme editor's `reloadThemeCss`, `MappHub.theme` clients and anything else linking the file all hit that 404.
- The shell now actually receives the theme. `www/index.html` links `theme.css` with `id="mapp-theme-css"` **before** `tokens.css`, and `js/bridge/themeCss.js` reloads it on `themeChanged` with the same double-buffering the SDK uses: a new `<link>` is inserted next to the old one, the old one is removed only after `onload`, and a failed load is dropped so the previous stylesheet survives.
- `MappSystemPlugin.onActiveThemeChanged` now invalidates the asset cache through `MappLocalAssetHandler.THEME_CSS` instead of a second copy of the string literal.

### Added
- `apps/shell-mobile/www/assets/theme.css.js` — the missing generator. It reads `config/active_theme`, then `themes/<id>`, and rebuilds the `:root` block: invalid declarations are dropped instead of throwing, a theme larger than 16 KB is truncated without producing broken CSS, a bad theme id never reaches the database, and a database error yields an empty `:root` rather than a 500. Rhino 1.7.15 runs it, so the file is plain ES5 and a test enforces that.
- `docs/themes.md`: new "Отдача theme.css" section — generator contract, ES5 constraint, cache invalidation and reload protocol.

### Changed
- `www/css/tokens.css` is now a thin alias layer: every `--app-*` token maps onto the matching `--mapp-*` token with the previous colour as `var()` fallback. If `theme.css` is missing or a theme does not define a token, the shell looks exactly as before; when a theme is applied, the shell follows it. `shell.setTokens` still wins, because it writes `--app-*` inline on `:root`.
- The active theme is `light` on a fresh install, so a new device now starts with a light window background instead of a dark one. Switch to `dark` in the theme editor to get the previous look.

### Not changed
- Launcher, market, console, dialogs, browser, sample game and the theme editor still set their colours literally and do not read `--mapp-*`. They will not follow the theme until they are migrated (TASK-016).

### Tests
- New `tests/theme/theme-css-generator.test.mjs` (12 cases): active-theme selection, `light` fallback, id validation, unsafe and malformed declaration filtering, database failure, oversized CSS, ES5-only source, a run after the native `export default` rewrite, generator entry point, shell `<link>` order and the token alias layer.
- `npm test`: 63 tests, all green.

### Known limitations
- Not verified on a physical Android device or an emulator. The theme editor and the shell window background are the places to look.
- Mini-apps that are not preinstalled are not updated by the shell. Update them from the Market.
- `release-manifest.json` still carries a `versionCode` that does not match the value the build computes from the version (`20033` vs `2000033`). Nothing reads it today, but the two should be reconciled.
