## MappHub Shell 0.1.0-beta.3

### Added (native layer, Android)
- `MappDatabaseHelper`: single database `mapp_system.db` (WAL) with tables `miniapp_storage`, `system_registry`, `system_kv`. Hard-coded keys removed.
- `MappPackageManager`: ZIP install into `noBackupFilesDir/miniapps/<app_id>/<version>/` via a temporary `<version>_temp` directory, Zip Slip protection, atomic version activation, cleanup of old versions.
- `GitHubPagesPathHandler` and `MappWebViewClient`: virtual hosts `https://mapp.local/...` (CORS `*`, `sdk.js`, `theme-tokens.css` from `system_kv`) and `https://miniapp-<app_id>.local/...` (clean URLs, nested folders, `404.html`).
- `MappSystem` plugin: storage, system, installMiniApp, uninstallMiniApp, getInstalledApps methods.

### Added (client)
- `miniapps/_sdk/sdk.js`: `window.MappHub.storage.*` and `MappHub.ui.getThemeTokens()`, subscription to theme changes.
- `apps/shell-mobile/www/js/bridge/MappHostBridge.js`: source check by `WeakMap<Window, appId>` and origin, `themeChanged` broadcast.

### Known issues
- The bridge is not yet connected to `runtime.js`: the current mini-app loader works with the old scheme.
- Native code was not compiled locally (no Android SDK); verification happens in CI.
