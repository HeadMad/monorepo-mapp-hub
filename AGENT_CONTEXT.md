# AI Agent Context & Developer Guide (MappHub Monorepo)

Welcome, AI Agent! This document serves as your primary entry point and instructions manual for maintaining, developing, and evolving the **MappHub** monorepo project.

---

## 📂 File-Based Task Management System (Crucial for Token Economy)
To prevent context window bloat and ensure precise task execution, tasks are organized into dedicated subfolders under `/tasks`:
- `tasks/backlog/` — Future and planned tasks.
- `tasks/in_progress/` — Currently active tasks being executed.
- `tasks/done/` — Successfully completed tasks.
- `tasks/deprecated/` — Outdated or duplicate tasks.

**AI Agent Rule**: When starting work, read only the active tasks in progress, move completed ones to `tasks/done/`, and avoid parsing unnecessary historical task files. Update the task's `Status` and acceptance checkboxes in the same commit as the code it describes.

## 🚀 Project Vision & Architecture
- **Thin Shells (`apps/shell-mobile` & `apps/shell-desktop`)**: Minimalistic host wrappers running an iframe runtime.
- **RPC Communication Bridge**: Telegram Bot API inspired asynchronous JSON-RPC protocol over `postMessage`.
- **Modular API Actions**: Stored under `apps/shell-mobile/www/js/api/<category>/<action>.js`, dynamically imported on demand.
- **Shared Bus**: `apps/shell-mobile/www/js/bridge/bus.js`, SDK `MappHub.bus.*`. Described in `docs/api/bus.md`.
- **Dialogs Mini-App (`com.mapphub.dialogs`)**: alerts, confirmations, the shell update prompt and the install panel. The shell talks to it over the bus through `DialogClient` (`apps/shell-mobile/www/js/dialogs/client.js`). `alert`, `confirm`, `install`, `checkUpdate` are wrappers over this exchange.
- **Preinstalled Mini-Apps**: a folder `miniapps/<name>` with `preinstalled: true` is packed by `scripts/pack-miniapps.mjs` into `apps/shell-mobile/www/preinstalled/` and installed on start (`installer/preinstalled.js`) when missing or older. Currently: `com.mapphub.console`, `com.mapphub.dialogs`.
- **First-Run Bootstrap & Permissions**: On first launch, the runtime checks for the launcher, loads its manifest, and presents a 2-step permission modal (with warnings if permissions are revoked).
- **Auto-Update & Beta Channels**: Supports checking `release-manifest.json` for shell updates with progress bars and seamless updates.

## 🛫 Release Procedure
1. Bump the shell version in `apps/shell-mobile/package.json` and `apps/shell-mobile/www/js/version.js` (the same value). If a mini-app changed, bump its `mappmanifest.json`. Otherwise installed copies are not updated.
2. Run `node scripts/pack-miniapps.mjs` and commit `apps/shell-mobile/www/preinstalled/`.
3. Run `npm test` in the repository root.
4. Write `docs/releases/v<version>.md`. The workflow uses it as release notes.
5. Push to `main`. `CHANGELOG.md` is generated by the bot (`changelog.yml`), do not edit it by hand.
6. Start `Build Android Shell APK` with `workflow_dispatch`. Pass `version` without the `v` prefix.
7. After a successful build, update `release-manifest.json` (`version`, `versionCode`, `betaVersion`, `betaUrl`, `changelog`) and the GitHub Pages catalog (branch `gh-pages`: `index.json` and the archives from `dist/miniapps/`).

Device checks are not automated. If a release was not checked on a device, say so in its release notes and in the task file.
